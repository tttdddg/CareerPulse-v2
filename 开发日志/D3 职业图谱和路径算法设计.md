## 二、候选路径生成规则

### 2.1 起点选择（从「可进入岗位」出发，不是从「当前岗位」）

```
1. candidates = repository.entry_roles()
2. 对每个 entry 节点，用 MatchService 计算 学生画像 vs 节点 required_skills 的 skill_gaps
3. 起点 = 能力跨度成本最小（Σ gap×difficulty 最小）的 entry 节点
   等价于「学生当前能力最匹配的可进入岗位」
4. 若学生已有 years_of_experience ≥ 1，起点可放宽到 level_range=junior
```
> 复用 `MatchService.calculate(student, node_as_job_profile)`，节点能力向量按 `JobProfile` 组装后喂入，**不重复实现维度对齐**。

### 2.2 搜索算法（受限 DFS，确定性）

```
目标节点 = 图谱中 job_title == JobProfile.normalized_title 的节点
          （或 industry + level_range 最接近目标岗位的节点）

search(start, goal, max_depth=6):
  路径栈去重（visited 集合，防环）
  深度上限 max_depth = 图谱节点总数（当前=10）
  vertical 边：level_range 必须严格递增（entry<junior<mid<senior<lead）
  lateral 边：同一路径内连续 lateral 跳数 ≤ 2
  收集所有简单路径，不取第一条即止（为评分保留候选）
```

### 2.3 防循环与限长
- **防环**：DFS 用 `visited` 集合；`vertical` 必须等级递增天然无环，环只可能来自 `lateral` 往返（A↔B），靠 visited 拦截。
- **限长**：`max_depth` 上限 = 节点数；超过即剪枝。另设 `max_lateral_consecutive=2`。

### 2.4 无法直接到达的处理
```
若 goal 不在图谱中 或 start→goal 无通路：
  1. fallback_goal = 与 goal 同 industry 且 level_range 最高的可达节点
  2. 若仍无：fallback_goal = 与 start 同 industry 的可达终点（放弃原目标，标注 path_type="extension"）
  3. 标记 data_quality_flags.append("target_not_in_graph:<job_title>")
  4. 生成的路径目标一致性得分按 §3.4 降为 0
```
> 不得虚构不存在的岗位节点（AGENTS.md「不虚构岗位」）。找不到就是「无法直达」，明确标记而非造数据。

### 2.5 三类路径（最少保证）
| 类型                   | 生成规则                                                     | 特点             |
| ---------------------- | ------------------------------------------------------------ | ---------------- |
| **直接路径 direct**    | start→goal 的最短 simple path（跳数最少）                    | 时间短、跨度集中 |
| **稳健路径 robust**    | 边 `risk_level` 全 low、`transfer_cost` 最低的路径（≤max_depth 内） | 风险低、可行性强 |
| **拓展路径 extension** | 至少含 1 条 `lateral` 边、终点为 goal 或 fallback_goal 的路径 | 横向转岗、备选   |

取三类中各自评分最高者 + 全局 Top-K（K=3），去重后输出 `candidate_paths`。

## 三、路径评分规则

> 冻结主公式不可动（`PathScore_base = GrowthValue − TransferCost − AbilityGapCost`），9 项维度中「能力跨度/时间」已含在主公式，其余作为**加性/乘性调整项**，全部确定性计算。

### 3.1 分项定义与数据来源

| 维度           | 计算                                                         | 来源                                    |
| -------------- | ------------------------------------------------------------ | --------------------------------------- |
| 当前能力匹配度 | `start 节点 = MatchService.overall_score(学生, start.required_skills)` | MatchService                            |
| 能力跨度       | `Σ_node Σ_k gap_k × difficulty_k`（复用 `skill_gaps`）       | MatchService + ability_tags             |
| 预计时间       | `Σ_node typical_duration + Σ_edge transfer_cost×6`           | 图谱字段                                |
| 目标一致性     | `1.0` 终点==goal；`0.5` 同 industry 异岗位；`0.0` 其他       | 图结构                                  |
| 用户偏好       | `+P_industry` 终点 industry==target_industry；`+P_job` 经过 target_job 节点 | `basic_info.target_industry/target_job` |
| 行业连续性     | `Σ_edge [source_industry==target_industry] / 边数`           | 边字段                                  |
| 地域约束       | 见 3.2                                                       | 缺失降级                                |
| 路径风险       | `Σ_edge risk(edge) + Σ_node risk(node)`，映射 low=0/medium=1/high=2 | 图谱 + trend                            |
| 数据置信度     | 见 3.3                                                       | 图谱数据完整度                          |

### 3.2 地域约束（诚实处理缺失）
```
若 desired_city 为空 或 所有节点 cities 为空：
  地域分不参与计算 → data_quality_flags.append("city_data_unavailable")
若 desired_city 非空 且 节点有 cities：
  region_fit = 命中节点数 / 节点数
  total_score += region_fit × REGION_WEIGHT(如 +5)
```
**当前仓库两者皆缺**，所以阶段3 落地时地域维度只能「标记缺失、不计分」，不虚构城市数据。

### 3.3 数据置信度
```
data_confidence = 1.0
  − 0.2 × (存在 required_skills 回退岗位画像的节点数)
  − 0.2 × (存在 risk_level 回退 trend 的节点数)
  − 0.3 × (使用了 fallback_goal)
clamp [0,1]；低于 0.5 时给该路径打 data_quality_flags.append("low_path_data_confidence")
```

### 3.4 总分合成
```
PathScore_base = GrowthValue − TransferCost − AbilityGapCost   # 冻结

total_score = PathScore_base
            + 用户偏好调整 (+)
            + 行业连续性 × 连续性权重 (+)
            + 地域命中 × 地域权重 (+)
            − 路径风险 × 风险权重 (−)
            × 目标一致性 (乘性, 0..1)

排序：total_score 降序 → time_estimate 升序 → path_id 升序（确定性）
```

## 四、3年 / 5年路径结构（CareerStage / CareerRoadmap）

### 4.1 CareerStage（对应冻结 `phase` 的扩展，需 ADR）

| 字段                   | 类型             | 来源                               | 说明                                               |
| ---------------------- | ---------------- | ---------------------------------- | -------------------------------------------------- |
| `stage_index`          | `int`            | Service                            | 1 起                                               |
| `year_label`           | `str`            | Service                            | 「第1年」…「第5年」                                |
| `target_role`          | `str`            | 图节点                             | 本阶段落点岗位                                     |
| `objectives`           | `list[str]`      | **Agent/LLM**                      | 阶段目标文字                                       |
| `key_abilities`        | `list[str]`      | Service                            | 本阶段要掌握的关键能力（来自节点 required_skills） |
| `current_gaps`         | `list[SkillGap]` | Service                            | 复用 MatchResult.skill_gaps，切片到本阶段          |
| `suggested_actions`    | `list[str]`      | **Agent/LLM**                      | 行动方向（阶段3仅方向，不给课程/资源）             |
| `completion_criteria`  | `str`            | **Agent/LLM**                      | 完成标志文字                                       |
| `risks`                | `list[str]`      | Service（风险枚举）+ Agent（措辞） |                                                    |
| `next_stage_condition` | `str`            | **Agent/LLM**                      | 进入下一阶段条件                                   |

### 4.2 CareerRoadmap（并行新增 `state.career_roadmap`，**不改冻结 `path_plan`**）

```
career_roadmap = {
  target_job: str,
  horizon: "3year" | "5year",              # 由 time_range 输入决定
  stages: list[CareerStage],                # 3年→3阶段 / 5年→5阶段
  candidate_paths: list[CandidatePath],     # 已排序
  selected_path_id: str,
  path_algorithm_version: "graph-search-v1"  # 沿用冻结
}
```
- **冻结 `path_plan` 仍由 PathAgent 并行产出**（兼容投影，结构照 §5.1），新旧消费者都不破坏。
- 阶段数 = 时间范围年数；每阶段 `target_role` = 选中路径在该年度应到达的节点（按 `typical_duration` 累计分摊到年度）。

### 4.3 时间分配（确定性）
```
horizon = 36 (3年) 或 60 (5年)
对选中路径节点序列，按 typical_duration 顺序累加，
累计到第 k 年边界时，取该节点为第 k 阶段 target_role；
超出 horizon 的剩余节点 → 放入最后一阶段的 next_stage_condition 提示。
```

## 五、确定性计算 vs LLM 解释边界

| 能力                                                         | 归属                      | 红线                                |
| ------------------------------------------------------------ | ------------------------- | ----------------------------------- |
| 起点选择、图搜索、防环、限长、路径去重                       | **PathService**           | LLM 禁止                            |
| 三类路径（direct/robust/extension）识别                      | **PathService**           | LLM 禁止                            |
| `PathScore` 全部分项、`total_score`、排序、`selected_path_id` | **PathService**           | LLM 禁止                            |
| 阶段数、`year_label`、`target_role`、`key_abilities`、`current_gaps`、时间分摊 | **PathService**           | LLM 禁止                            |
| `objectives`/`suggested_actions`/`completion_criteria`/`next_stage_condition`/路径 `reason` | **PathAgent（LLM）**      | 仅文字                              |
| `risks`                                                      | Service 枚举 + Agent 措辞 | 风险来源必须可追溯（trend/边 risk） |
| 缺失城市、缺失能力向量、fallback_goal 的标记                 | **PathService**           | 不虚构                              |

> 与 MatchService 一致的红线：**数值/结构一律 Service 算，LLM 只写自然语言，严禁 LLM 覆盖数值或伪造图谱节点**。

## 六、模块职责边界

| 模块                      | 职责                                                         | 不做什么                            |
| ------------------------- | ------------------------------------------------------------ | ----------------------------------- |
| **CareerGraphRepository** | 加载/校验 `career_graph.json` → 邻接表；`entry_roles/next_roles/parallel_roles` 查询；`required_skills` 缺失时回退岗位画像；暴露 `node_by_title()` | 不评分、不搜索、不调用 LLM          |

**与 MatchAgent 的关系**：PathAgent 复用 MatchAgent 已产出的 `match_result`（含 `skill_gaps`），但**不依赖 MatchAgent 的内部实现**，只消费 `state.match_result` 数据。

**CareerGraphRepository**
- 节点/边数量校验、环检测、孤立节点报错
- `entry_roles/next_roles/parallel_roles` 查询正确
- `required_skills=None` 时回退岗位画像；回退失败 → 报错

- 冻结 `PathScore_base` 分项单调性（growth↑→分↑，gap↑→分↓）
- 目标一致性：终点==goal→1.0，同行业→0.5，否则 0
- 地域：`desired_city` 空 → 不计分 + flag；节点 cities 空 → 不计分 + flag
- 数据置信度：回退节点/fallback_goal 触发扣分
- 排序确定性：同输入 10 次结果逐字节一致

**PathService 阶段化**
- 3 年→3 阶段、5 年→5 阶段
- `current_gaps` 与 `MatchResult.skill_gaps` 切片一致
- `key_abilities` ⊆ 节点 required_skills
- 时间累计不超 horizon

**PathAgent**
- 成功：LLM double 返回合法文字 → 数值与 PathService 一致
- LLM 失败：fallback 用固定文字模板，数值仍为 Service 结果
- 红线：恶意 LLM 输出无法改写 `total_score`/排序/图结构
- 隐私：日志无手机号/邮箱/身份证/完整简历

**回归**
- `path_plan`（冻结结构）仍产出，字段不缺失
- `CareerState.apply_agent_data` 白名单含新字段
