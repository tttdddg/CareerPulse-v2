## 3. 完整调用链

### 3.1 职业能力主链路

```text
已验证 StudentProfile
→ MatchAgent
→ MatchService.calculate
→ match_result 写入 CareerState
→ PathAgent
→ PathService.calculate
→ career_roadmap / path_plan / learning_plan 写入 CareerState
```

验证结果：

- 阶段3 Match/Path Agent、HTTP E2E、TBox stage3 tools、MCP server：`40 passed`。
- Match 的 overall score、skill gaps、priority 与 Path 的路径分数全部和 Service 独立计算结果相等。
- ProfileAgent 独立全绿仍被既有 prompt 文件缺失阻塞，详见第 12 节。

### 3.2 能力缺口到训练题

```text
match_result.skill_gaps[].dimension（保持现有顺序）
→ CareerMCPToolService.generate_and_score_training(generate mode)
→ CareerOrchestrator 临时注入 training_type
→ TrainingAgent 从 State 提取 ability gaps
→ TrainingService.generate
→ TrainingTask 写入 training_plan.trainings
```

连续验收使用真实 MatchService 输出。测试将 TrainingAgent 的 generate 调用参数与 `match_result.skill_gaps[].dimension` 逐项比较，并用冻结 TrainingService 对同一输入生成 expected task；任务完全相等，target abilities 与真实 gaps 存在交集。

### 3.3 训练回答到评分

```text
training_id + user_answer
→ State 查找当前 TrainingTask / evaluation criteria
→ mock LLM 只返回 dimensions[].dimension / coverage / reason
→ TrainingService.score(agent_analysis)
→ dimension_scores / total_score / ability_updates
→ training_plan.latest_score 写入 State
```

合法 LLM signal 使用五档 coverage。测试把 Agent 实际传给 Service 的 analysis 再独立交给新 TrainingService 实例计算，逐字段证明：

- `dimension_scores` 来自 TrainingService
- `total_score` 来自 TrainingService
- `ability_updates` 来自 TrainingService
- Agent 的自然语言反馈不能覆盖上述值

### 3.4 能力缺口到资源

```text
match_result.skill_gaps[].dimension
→ CareerMCPToolService.recommend_learning_and_job_resources
→ ResourceService.recommend_resources
→ learning_resources / job_resources
→ certificate_suggestions / data_quality_flags
→ resource_result 写入 State
```

资源调用不经过 LLM，也没有新建 ResourceAgent。真实匿名 Match 结果可返回 learning resources，并保留 `no_resource_for_tag`、`job_resources_unavailable` 等冻结 flag。

### 3.5 反馈、调权与成长快照

```text
用户输入 satisfaction / ratings / comments
→ Orchestrator 临时 stage_input
→ FeedbackAgent 从 State 自动读取：
   session_id / user_id / skill_gaps
   training_target_abilities / overall_score / abilities
→ FeedbackService.save_feedback
→ feedback_saved / updated_priorities / growth_snapshot / flags
→ feedback_result 写入 State
```

连续验收使用 `satisfaction=4`、`training_rating=2`。测试证明 FeedbackService 收到的 skill gaps、training targets 与 overall score 都来自同一 session 的真实 State；priority 更新和 growth snapshot 与 Service 原始返回完全一致。首次成长快照为 stable，并带 `first_growth_snapshot`。

## 10. fail-safe 验证

| 场景 | 结果 |
|---|---|
| 无 match_result 请求资源 | `MATCH_RESULT_NOT_FOUND` 安全 envelope |
| 无当前 training / training ID 不存在 | `TRAINING_NOT_FOUND`，不运行 Agent |
| 非法 training_type | Pydantic 边界拒绝，不进入 Orchestrator |
| 非法 rating | Pydantic 边界拒绝，不进入 Orchestrator |
| user_answer 隐私 | 评分失败但无原文泄漏 |
| comments 隐私 | 保存失败，State 不写 feedback result |
| LLM 无响应 | TrainingService fallback；反馈文字模板 fallback |
| LLM 非法 coverage | Agent 将不可用 signal 降为 `None`，Service fallback |
| LLM 输出数值字段 | Service 返回 `agent_analysis_rejected:numeric_field` 并 fallback |
| Resource unknown tag | 空资源 + `unknown_tag` flag，不抛异常 |
| ResourceService error | `RESOURCE_SERVICE_ERROR` 安全 envelope |
| 新 session 无历史 growth | stable + `first_growth_snapshot` |
| session 交叉使用 training ID | 拒绝，训练/反馈不跨 session 污染 |

所有自动化验证均使用 mock/offline LLM，没有调用外部模型或公网。

## 13. 百宝箱接入所需能力清单

百宝箱下一阶段只需为以下现成内部方法增加薄 MCP/HTTP adapter：

### `generate_and_score_training` — generate mode

调用方输入：

- session_id
- user_id
- training_type
- 可选 trace_id

系统从 State 自动补：student/job profile、match result、有序 ability gaps。

### `generate_and_score_training` — score mode

调用方输入：

- session_id
- user_id
- training_id
- user_answer
- 可选 trace_id

系统从 State 自动补：当前 TrainingTask、type、evaluation criteria、target abilities。

### `recommend_learning_and_job_resources`

调用方输入：

- session_id
- user_id
- 可选 trace_id

系统从 State 自动补：有序 skill gap dimensions、target job。

### `save_growth_feedback`

调用方输入：

- session_id
- user_id
- satisfaction
- 可选 path_rating / training_rating / resource_rating / comments / trace_id

系统从 State 自动补：skill gaps、training target abilities、abilities、overall score；completed counts 仍按冻结规格的安全默认值 0，不虚构完成次数。

上述能力统一返回阶段3风格的 success/error envelope，并已具备 session identity、trace 幂等、超时和 State 持久化。
