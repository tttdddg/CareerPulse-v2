## 6. CareerState

状态经查询依次确认：

```
INITIALIZED
→ MATCH_COMPLETED
→ PATH_COMPLETED
```

最终状态为 `PATH_COMPLETED`。失败场景统一使用 `FAILED`，并写入可判断的 `error_type`。

## 7. AgentRunLog

持久化日志包含两条：

- `MatchAgent / MatchService / success`
- `PathAgent / PathService / success`

均包含 `duration_ms`、状态、工具摘要及错误字段。日志验证未包含姓名、画像证据、完整简历、API Key 或模拟私密异常文本。Agent/Service 双重失败时会记录脱敏错误类型。

## 8. 数据库持久化

- 本地/Demo 使用真实文件型 SQLite，不再静默回退到内存。
- 状态和 Agent 日志在同一事务写入。
- 重建 Repository、Orchestrator 和 FastAPI 后，仍能读取相同 `PATH_COMPLETED` 状态和完整 roadmap。
- 数据库日志写入失败测试返回 HTTP 503；事务回滚后仍为写入前 `INITIALIZED` 状态，匹配结果和日志均未部分落库。
- PostgreSQL 新增 V003 迁移，包含 `career_state`、`service_name` 和幂等 `run_key`。

## 9. 异常场景结果

- 学生画像不存在：404，`STUDENT_PROFILE_NOT_FOUND`
- 岗位画像不存在：404，`JOB_PROFILE_NOT_FOUND`
- 学生画像不完整：422，`STUDENT_PROFILE_INCOMPLETE`
- 岗位能力为空：Schema 422
- LLM失败/离线：主链正常完成
- 目标岗位不在图谱：返回明确 `target_not_in_graph` 和 fallback 标志
- 无可达路径：`no_reachable_path`，候选为空，不伪造路径
- 数据库失败：503，事务正确回滚
- 重复相同请求：幂等返回，日志仍为2条
- 同 Session 冲突画像：409
- 非法 ID、额外字段：422
- 未匹配直接生成路径：409，`MATCH_NOT_COMPLETED`
- MatchService执行及fallback均失败：422，状态和日志均为失败
