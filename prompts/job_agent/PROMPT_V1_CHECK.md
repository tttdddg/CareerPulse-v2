# JobAgent Prompt V1 三岗位输入检查

检查方式：读取 `backend/app/data/jobs_demo.json` 的三份匿名岗位样例，将岗位名称放入 `job_name`，将演示岗位描述与既有能力要求整理为匿名模拟 JD，使用非统计性的匿名趋势上下文检查模板组装和事实边界。仓库目前没有独立岗位趋势资料数据文件，因此以下趋势文字只用于结构检查，不代表真实市场结论，也不用于验证趋势准确率。

## 样例一：AI 产品经理

- `job_name`：AI产品经理；行业人工智能；演示岗位 ID 91001。
- 模拟 `job_description`：负责产品规划、需求分析、用户研究和项目协作；要求使用数据支持决策，并理解大模型应用场景。该内容由演示岗位能力项整理，不是线上真实 JD。
- 模拟 `trend_context`：匿名资料仅描述大模型应用和数据驱动决策受到关注，未提供招聘数量、增长率、年份或 AI 替代率。
- 可进入岗位能力：产品规划、需求分析、数据驱动决策、大模型应用、用户研究、沟通表达、项目管理；每项 evidence 只能引用模拟 JD。
- 可进入趋势：仅在趋势上下文明确支持时使用大模型应用、数据驱动决策；不得把趋势热度写成当前 JD 的新硬性要求。
- 禁止推断：RAG、Agent、MCP、模型微调、具体增长率、录用概率、用户匹配度。

## 样例二：数据分析师

- `job_name`：数据分析师；行业电子商务；演示岗位 ID 91002。
- 模拟 `job_description`：负责数据分析、SQL 查询、Python 数据处理和数据可视化，并向业务方表达分析结论。
- 模拟 `trend_context`：匿名资料描述自动化工具可能减少重复整理工作，业务理解和结论解释仍值得关注；没有量化统计。
- 可进入岗位能力：数据分析、SQL/数据库、Python、数据可视化、沟通表达。
- 趋势归纳只能使用“可能”“值得关注”，AI 风险说明必须承认资料没有量化结论。
- 禁止推断：机器学习、深度学习、电商行业经验、具体工具品牌、岗位需求增长百分比。

## 样例三：后端开发工程师

- `job_name`：后端开发工程师；行业企业服务/SaaS；演示岗位 ID 91003。
- 模拟 `job_description`：负责 Java 后端开发、数据库使用、API 设计和基础 Linux 环境操作，使用 Git 协作。
- 模拟 `trend_context`：匿名资料描述云原生和自动化开发工具可能影响岗位技能结构，但没有说明当前 JD 要求 Docker/K8s 或云计算。
- 可进入岗位能力：后端开发、Java、SQL/数据库、API设计、Linux/运维、Git/版本控制。
- Docker/K8s、云计算若仅出现在趋势资料，只能进入有依据的趋势技能列表，不能加入当前 required abilities 或 evidence。
- 禁止推断：Spring、微服务、分布式系统、具体工作年限、架构师级别、岗位增长率。

## 输入结构检查

- 三份输入均预留并填充 `job_name`、`job_description`、`trend_context`，无残留模板变量。
- 数据块使用独立标签，system prompt 明确把块内内容视为数据而非指令。
- 输出顶层固定为 `job_profile` 和 `trend_result`，可分别写入 CareerState 对应字段。
- required abilities 与趋势技能均限定为现有标准能力标签；能力 evidence 与 trend context 来源隔离。
- 权重总和必须为 1.0，等级、importance、AI 风险枚举与当前 JobSchema 对齐。

## 主要幻觉风险

- 把岗位名称或行业常识自动展开成 JD 没有要求的技术栈。
- 把趋势资料中的热门技能写进当前岗位 required abilities，造成“趋势即硬门槛”。
- 为满足权重和或能力数量编造能力，再为编造能力补写 evidence。
- 根据“高级”“精通”或年限词直接给 required_level 4–5，而忽略具体职责证据。
- 把非量化趋势材料改写成招聘增长率、薪资变化或 AI 替代比例。
- 在缺少趋势资料时仍给出确定的未来判断；当前 Schema 没有 unknown 风险枚举，只能使用 `medium` 中性占位并在 detail/data_source 中明确资料缺失。
- 将 Demo 岗位样例误称为真实招聘 JD 或真实市场趋势。
