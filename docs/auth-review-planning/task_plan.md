## 最终结论
- 保持现网 8000 A02 Core 服务和现有评审域名不动。
- 新建 8001 Web BFF/Identity 服务作为浏览器认证与 Vue API 适配边界；由服务端持有 Core/MCP/TBox 凭据，调用现有核心能力，不复制 Match/Path/Training 逻辑。
- 身份数据优先进入同一 PostgreSQL 实例的独立 `identity` schema，而不是另建长期业务事实库；正式开放 Profile 首次写入前，必须按数据库契约完成用户绑定与幂等回执的同事务设计并获得技术负责人批准。
- 前端只能部署到 BFF 同源入口，不能直接把 `/api` 指向当前 8000 Core。
- 评审期间可以开发、测试并部署独立的 BFF/前端 staging 域名；涉及核心数据库正式写入或 Core 契约变更的切换留到评审结束后，通过兼容版本和独立端口验证再完成。
