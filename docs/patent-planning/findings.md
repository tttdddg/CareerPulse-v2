# 调研发现

## Skills

- Codex 官方说明支持个人 Skill 和仓库级 `.agents/skills`；当前环境自带的 `skill-installer` 默认安装到 `$CODEX_HOME/skills`，也可用 `--dest` 指定位置。
- 安装器允许仓库根作为 Skill：`--path . --name <name>`；会验证根目录存在 `SKILL.md` 并完整复制文件树。
- `patent-disclosure-skill` 的仓库根即 Skill 根；完整功能依赖其嵌套 `skills/patent-*`、脚本和 references，不能只复制根 `SKILL.md`。
- `patent-disclosure-skill` 主依赖为 Python 3.9+ 和根 `requirements.txt`；申请文件子 Skill 复用 PyYAML、python-docx、Playwright。CNIPA 检索还可安装专用 requirements 并探测 Chrome/Edge。
- `Paper-to-patent-Skill` 也是根级 Skill，`SKILL.md` 中实际名称为 `paper-to-cn-patent`，要求 Python 3.10+；优势是证据台账、支持关系验证、公式、附图和分立 DOCX。
- `patent-writer` 根目录含 `SKILL.md`，但原生安装脚本面向 Claude Code，并要求外部检索 token、在线 Mermaid 服务；在 Codex 中更适合完整仓库安装后显式调用或仅借其 QC 规则。
- 官方文档提示 Skill 依靠 `name`/`description` 自动触发；安装过多相近 Skill 会造成路由重叠，因此不建议三套同时隐式启用。

## 项目证据

- 当前工作树未检索到 `DPO`、`Direct Preference Optimization` 或 `Memobase` 的直接实现标识。
- 已存在与偏好/反馈相关的链路：`FeedbackAgent`、`FeedbackService`、`save_growth_feedback`、用户满意度及分项评分、成长档案和学习优先级更新。
- 已存在与长期画像/记忆相邻的能力：历史学生画像合并、`CareerState`、成长档案、历史记录服务、结构化画像 Schema。
- 当前已有实现明确把评分、路径、反馈优先级等确定性计算放在 Service 层，LLM 只负责受约束的提取、解释和决策；这可能成为技术方案边界的重要组成，但不能直接等同于 DPO 或 Memobase。
- 仓库已有大量测试、API/Agent 合同和开发日志，可作为代码证据与时间证据来源。
- 工作树存在用户既有未提交修改，本任务不得覆盖或混入这些改动。

## 专利方向

- “优化的 DPO 模型”目前更像计划中的训练/对齐方案；在找到训练代码、损失函数、偏好对构造、基线实验和性能结果前，不能声称已经在本项目实现。
- “Memobase”需先澄清是外部开源组件、内部模块名称，还是泛指长期记忆底座；现有项目只证明存在相邻的画像、状态和反馈存储能力。

## 第一轮代码证据细化

### 与 DPO 相邻但不等于 DPO 的能力

- `FeedbackService.save_feedback` 接收满意度、路径/训练/资源评分和评论，并以确定性规则调整训练目标优先级、生成成长趋势快照。
- `FeedbackAgent` 只把状态投影到 Service，校验结果并生成一句自然语言解释；异常时不会伪造反馈已保存。
- 当前反馈是 1–5 分绝对评分，没有 `chosen/rejected` 偏好对、参考模型、策略模型、DPO 损失函数、训练循环、离线评测或模型权重产物。
- 因此，现有反馈闭环可以作为未来 DPO 数据构造和安全约束的项目基础，但不能作为“优化 DPO 模型已经实现”的证据。

### 与 Memobase 相邻但不等于统一记忆底座的能力

- `ProfileService` 可以合并历史画像证据，对能力标签做标准化、去重、证据溯源、置信度计算和隐私脱敏。
- `HistoryService` 从数据库查询匹配历史及完整快照；迁移文件定义了 `growth_archives`、`user_feedback`、`training_records`、`learning_plans` 和 `agent_logs` 等表。
- 当前 `FeedbackService` 自身用进程内字典保存反馈和成长快照；代码中尚未看到其写入上述数据库表。
- 当前能力分散在画像合并、会话状态、历史查询和若干业务表中，尚未形成统一的记忆抽取、存储、检索、冲突消解、遗忘/衰减和权限隔离流水线。
- 因此可以构思“职业生涯纵向记忆底座”，但需把现有模块与拟新增机制明确分开。

### Memobase 的外部现有技术风险

- `memodb-io/memobase` 已是公开的 Apache-2.0 开源项目，公开描述了用户画像式长期记忆、事件时间线、缓冲批处理、profile/context API、FastAPI/Postgres/Redis 和低延迟上下文装配。
- 不能把该开源项目本身、通用“画像 + 事件”结构或其已公开流程当作 CareerPulse 自己的发明点。
- 可申请的方向必须是 CareerPulse 在其上新增且在公开日前尚未公开的具体技术改进，例如职业证据可信度、跨阶段记忆冲突消解、确定性评分隔离、隐私分级遗忘、面向路径规划的记忆投影等，并需先做现有技术检索。

## 候选专利一：DPO 优化方案

### 暂定技术主题

“一种受多源可信度和确定性约束的职业导航模型自适应偏好对齐方法、系统、设备及介质”。

### 初步技术链路

1. 从用户明确评分、路径采纳/放弃、训练完成情况和结构化服务结果中形成候选反馈事件。
2. 将候选回答交由 Match/Path/Training 等确定性 Service 以及 Pydantic/JSON Schema 门禁验证，剔除分数幻觉、字段不一致、隐私泄露和状态非法的样本。
3. 结合来源可信度、时间新鲜度、用户反馈强度、跨阶段一致性形成偏好对置信向量。
4. 构造 `chosen/rejected` 偏好对，并按置信向量计算样本级权重、间隔或自适应 DPO 温度/β。
5. 在参考模型约束下训练策略模型，训练产物必须通过与线上相同的结构和确定性约束校验。
6. 用普通 DPO、SFT 和无自适应权重版本作对照，评估格式合法率、约束违反率、偏好胜率、稳定性和训练成本。

### 可能形成创造性的位置

- 不是单纯换一个 DPO 超参数，而是把多源职业反馈转成可审计偏好对的构造机制。
- 把确定性业务 Service 结果作为训练样本门禁和线上推理共同约束，降低离线训练与线上执行偏移。
- 样本级可信度参与 DPO 目标，而不是所有偏好对等权处理。

### 正式撰写前必须补齐

- 精确损失函数、权重/β计算式和取值范围。
- 偏好对生成代码、训练脚本、模型与参考模型信息。
- 至少一组基线、消融、重复实验及原始结果。
- 哪些指标体现计算机系统或模型训练的技术效果，而非单纯用户满意度。
- 发明完成时间、参与人和首次公开时间。

## 候选专利二：职业生涯时序证据记忆

### 暂定技术主题

“一种面向职业导航多智能体的时序证据记忆管理与上下文装配方法、系统、设备及介质”。

### 初步技术链路

1. 从简历、对话、测评、岗位分析、训练结果和反馈中提取原子记忆事件。
2. 每条事件附带来源位置、事件时间、有效期、置信度、隐私等级、职业阶段和可见 Agent 范围。
3. 将原始证据、用户陈述、确定性 Service 结果和 LLM 推断分层存储，禁止推断覆盖事实或确定性分数。
4. 对相互冲突的学历、技能、目标岗位和时间事件执行基于来源等级、时效及用户确认的冲突消解，保留版本和审计轨迹。
5. CareerOrchestrator 按 Profile/Match/Path/Training/Feedback 任务构造角色分域查询，并在令牌预算和隐私预算内装配最小上下文包。
6. 反馈后更新成长快照和记忆有效性，不直接改写不可追溯的历史事实；支持过期、撤回和用户删除。

### 可能形成创造性的位置

- 将职业纵向证据、职业阶段与多 Agent 权限边界统一进记忆对象和检索过程。
- 对确定性评分、原始证据和 LLM 推断进行不可混淆的分层与冲突处理。
- 根据任务、令牌预算、隐私预算和时间有效性生成最小上下文，而不是简单返回完整画像或向量检索结果。

### 正式撰写前必须补齐

- 统一记忆对象 Schema、状态机、冲突消解规则和删除/遗忘策略。
- 与现有 Memobase/Mem0/Zep 等系统的逐项差异表。
- 数据库存储、索引和上下文装配实现。
- 上下文 token 数、查询时延、矛盾率、错误引用率、隐私泄露率等对照实验。
- 明确哪些内容是当前代码已有、哪些是后续新增，保留版本证据。

## 第一件专利最终保护构思

- 发明名称最终确定为“一种职业路径偏好优化方法”。
- 独立方法权利要求以六步闭环为核心：获取职业状态和反馈、构造候选/反事实层级偏好对、计算稳定性权重、计算可执行性约束向量、调制 DPO 训练、生成并校验多阶段职业路径。
- 独立系统、电子设备和计算机可读存储介质权利要求分别承接方法步骤，共十项权利要求，避免超过十项产生附加权利要求费。
- 说明书保留五个可编辑公式，但把具体系数和模型底座放在实施例或待确认清单中，避免用未经实现验证的细节不当限缩保护范围。
- 现有材料只能支持方案构思和可实施描述，不能支持具体性能提升比例；正式提交前应补训练代码、参数、样本规模、基线和消融结果，并由专利代理师复核新颖性、创造性及充分公开。
