# 前端演示模式发现记录

## 已知现状

- 前端已有数据输入、人岗匹配、路径图谱、成长计划、职场训练和成长档案页面。
- 数据输入页通过 `front/src/api/modules/career.ts` 请求后端，并将结果写入 `front/src/stores/analysis.ts`。
- 现有工作树包含其他任务的后端与部署改动；本任务只修改前端演示相关文件。
- 已确认匿名案例：目标岗位为 AI 应用开发工程师（AI Agent / FDE），匹配分 81.67，置信度 88.12%。
- 隐私要求：不得提交真实简历身份和联系方式。
- `front/src/api/request.ts` 是所有职业 API 的统一请求入口，适合在这里切换本地 Demo 适配器，避免逐页硬编码。
- 路由需要本地登录 token；Demo Mode 应自动建立匿名演示会话，确保可直接打开 `/app/input`。
- `analysis` Store 当前不持久化，刷新后会丢失路径访问权限；Demo Mode 需要统一预载或恢复上下文。
- 职场训练当前明确标记为“HTTP API 未接入”，需要在 Demo Mode 下提供独立可用的适配器。
- 构建脚本包含 `npm run typecheck` 与 `npm run build`，可作为主要前端验收。
- Career API 共需模拟岗位列表/画像/图谱、学生上传、匹配、报告、推荐、历史八类请求；统一请求层可以保持所有现有标准化逻辑不变。
- 路径页要求每个选中岗位图谱同时包含节点和边；节点 ID 最好使用纯数字或 `job-<id>`，便于继续读取岗位详情。
- 成长档案由历史报告列表自动生成折线数据，因此提供 2026-02、2026-06、2026-09 三条报告即可形成 50.00 → 75.42 → 81.67 趋势。
- 岗位库会用多个关键词并行查询；Demo 请求层需对任意关键词返回可过滤的稳定岗位集合，避免空页面。
- 训练页只依赖 `TrainingApiAdapter`，可在不触碰 Career 请求层的情况下启用三类本地任务和确定性关键词覆盖评分。
- 1440×1200 实际渲染检查显示：演示徽标、匿名案例卡、上传区、四个输入框和底部分析操作均无重叠或截断。
- 青绿色 Demo 标识与原有蓝紫操作色形成清晰语义区分，不改变现有页面整体设计语言。
- 当前项目未安装 Playwright/Puppeteer；本轮以严格类型检查、默认/演示双构建和无头 Edge 页面截图作为前端验收证据。
